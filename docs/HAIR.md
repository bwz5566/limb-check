# 头发：发色、发长

招聘方要求（2026-10）：红、紫、绿、黄等过曝光色不录用，棕褐、黑色系正常；男生不留长发。
标准全部在 `configs/policies/hair.yaml`，条件还在讨论，改标准只改这个文件（改完运行 `limbcheck export-web-config`，再跑 `pytest`）。

## 采集

网页 demo 的"头发近景（正面 → 背面）"步骤，坐在桌前也能做：

1. 摘下帽子、发箍，正对镜头，头顶到双肩都在画面里 → 采集 `head_front`
2. 转身背对镜头（坐着可以转椅子）→ 采集 `head_back`，扎起来的长发、后脑的挑染要从背面才看得到

头顶出画、肩膀不在画面里时会提示调整摄像头或坐姿。背对镜头时浏览器的姿态模型常找不到人，转身后等 6 秒照常采集。

## 判定（服务端，`limbcheck/appearance.py`）

**只看受检者本人的头发**：分割模型（MediaPipe 多类别人像分割）给出头发区域，只保留面积最大的那个人；
染成亮色（金、粉、红）的头发分割模型常归到"其他"类，所以头部范围内的"其他"也算头发。帽子、发箍、彩色发夹也会被算进去，所以采集时提示摘下。

**白平衡**：摄像头偏色时黑发会被拍成紫色（实测的办公室摄像头就是这样）。用面部肤色（背面用脖子）估计偏色：
把肤色的色相校正到 48 度，头发按同样的 RGB 倍数校正，每个通道最多校正 1.35 倍，避免把真染的颜色"校正"掉。

**按颜色分类**：每个头发像素换算到 Lab 的亮度、彩度、色相，按顺序归类：

| 颜色 | 结论 | 大致范围 |
| --- | --- | --- |
| 黑色、黑 / 深色（含反光）、灰白、棕色 / 棕褐 | 正常 | 暗或彩度低；棕色为暖色调、彩度 ≤ 30、亮度 ≤ 55 |
| 金色 / 黄色 | 拦截 | 色相 55–110 度、彩度 ≥ 22、亮度 ≥ 52 |
| 红色 / 酒红 / 橙红 | 拦截 | 色相 5–65 度、彩度 ≥ 24 |
| 紫色 / 粉色 | 拦截 | 色相 305–5 度、彩度 ≥ 20 |
| 绿色 | 拦截 | 色相 100–200 度、彩度 ≥ 16 |
| 蓝色 | 拦截 | 色相 200–305 度、彩度 ≥ 18 |
| 其他 | 人工核验 | 以上都不符合 |

**结论**看"拦截颜色"占头发的比例：≥ 35% 整体染色，8%–35% 挑染 / 局部染色，< 8% 自然发色。
比例落在 8% 附近（±40%）交人工核验；无法归类的颜色占 35% 以上也交人工核验。

**发长**：发尾（头发最低处）在"头顶 → 肩线"之间的位置，短发 < 0.75，及领 0.75–0.95，及肩 0.95–1.2，过肩 > 1.2。
肩线优先用肩关节关键点，背面找不到时从人体轮廓估算（宽度超过头宽 2 倍处）；头顶出画时按眼睛位置估算。

**男生长发**：只在招聘方填写了性别"男"时判定（系统不从图像判断性别）。默认发尾及肩或更长（≥ 0.95）不录用，0.85–1.05 交人工核验。
常见的更严标准"男生后不过领"：把 `length.rules.male.max_ratio` 改成 0.8 左右。没填性别或性别为女时发长只记录。

**置信度上限 0.8**（`dyed.max_confidence`）：发色只有分割 + 颜色统计一路，低于仲裁的直接判定线（0.85），
所以拦截项一律是"疑似问题·待人工确认"，自然发色置信度高时直接"满足"。用真实染发样本校准后再调高。

## 测试

- 单元测试 `tests/test_hair.py`：合成的分割图覆盖每种颜色、挑染、阈值附近、摄像头偏色、背景里别人的头发、分割成"其他"类、
  男生长发、未填性别、头顶出画、背面无关键点
- 真人照片：实测者的 3 张网页截图（偏紫的办公室摄像头）都判自然发色、短发；
  同一张照片改成 12 种发色（加上画面原有的偏色）：红、酒红、紫、粉、绿、蓝、金色整体染色，红色、金色挑染都判对；
  自然棕、浅棕、灰白、少量挑染（< 8%）判自然

## 已知限制

- 阈值是用改色照片定的初值，需要真实染发样本（尤其浅棕 / 亚麻、酒红、暗紫）校准
- 发长没有真人长发样本验证过；背面视角的分割效果需要实测
- 光头或头发极短时头发像素太少，结论为"无法判断"，交人工
- 大模型复核（L2）的提示词仍只判发色，没有发长；需要时出 v3 提示词
