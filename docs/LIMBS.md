# 四肢完整性与肢体协调性

第 2 步（2026-10-27）。四肢、手部的检测都不依赖发色、纹身、疤痕、指甲这些仍在讨论的外观条件，可以先独立上线。
阈值都在 `configs/thresholds.yaml`（`pose`、`motion` 两段），改完运行 `limbcheck export-web-config`。

## 1. 四肢完整性（每个身体视角一张图）

关键点模型在肢体缺失时常会"脑补"出关节，所以用四条互相独立的证据交叉检查，任一条报问题即记疑似：

| 证据 | 做法 | 能发现 | 阈值 |
| --- | --- | --- | --- |
| 关键点可见度 | 肩、肘、腕、髋、膝、踝的可见度 | 缺失时模型给出的低可见度"脑补"点 | `pose.min_visibility` 0.55 |
| 双脚 | 脚跟、脚尖点可见度（只在正面站立视角） | 缺脚、足部残缺 | `pose.foot_min_visibility` 0.4 |
| 伸直姿势下的关节弯折 | 站立、侧平举、上举时肘 / 膝角度 | 前臂、小腿缺失时关键点模型把腕 / 踝"折"回上臂、大腿上；关节伸不直 | `pose.min_straight_angle` 120° |
| 人体轮廓复核 | 人体分割掩码，每段肢体 1/4、1/2、3/4 处采样 | 关键点画在背景上（远端缺失） | `pose.contour_min` 0.5 |
| 左右长度比 | 大臂、小臂、大腿、小腿左右比 | 短缩、残缺 | `pose.limb_symmetry` [0.75, 1.33] |

- 关节、脚落在画面外 → 视为没拍全，提示重拍，不算疑似（脚出画只记录，不影响结论）。
- 用 MediaPipe 官方测试图做过实测：原图正常；把右前臂擦掉后，关键点模型把右腕"折"回到大臂上，轮廓复核查不出（点都落在身上），
  "关节弯折"规则查出来了（疑似·待人工确认）。
- 离线流水线节点：`limbs.pose`（可见度、双脚、弯折、长度比）+ `limbs.contour`（人体分割，需要 `segmenter`）；网页 demo 用姿态模型自带的分割掩码，规则相同。

## 2. 肢体协调性（动作序列分析）

网页 demo 在每个身体动作步骤里按约 15 帧 / 秒记录关键点轨迹，检测结束后交服务端分析（`limbcheck/motion.py`）。
新增两个动作：**原地高抬腿**（下肢交替与节律）、**交叉摸肩**（跨中线动作，上肢交替与节律）。

| 动作 | 指标 | 疑似问题 | 阈值（`motion` 段） |
| --- | --- | --- | --- |
| 双臂侧平举 → 上举 | 左右外展角、肘角、左右高度差 | 抬不到位（侧平举 < 70°、上举 < 140°）、肘伸不直（< 140°）、左右差 > 25° | `arms` |
| 单腿抬起 | 抬腿比例（大腿抬平 = 1）、抬腿时髋部左右晃动 | 抬腿 < 0.5、左右差 > 0.35、晃动 > 0.15 躯干长 | `legs` |
| 深蹲后起立 | 下蹲深度、最低点左右膝角差、身体侧移 | 深度 < 0.25 腿长、膝角差 > 25°、侧移 > 0.15 躯干长 | `squat` |
| 原地高抬腿 | 次数、左右交替比例、间隔变异系数、左右次数 | 次数 < 6、交替 < 70%、变异系数 > 0.45、左右差 > 2 次 | `march` |
| 交叉摸肩 | 次数、左右交替比例、间隔变异系数 | 次数 < 4、交替 < 70%、变异系数 > 0.5 | `cross_touch` |
| 握拳 / 对捏 | 是否在时限内完成 | 超时 | — |

- 结论：只有关键点一路证据，**发现问题只给"疑似问题·待人工确认"**，不自动判不符合；≥ 2 个身体动作都正常 → 置信度 0.85，标准档直接"满足"。
- 报告新增"肢体协调性（动作分析）"表：每个动作的帧数、指标和结论，可对照分步证据截图复核。
- 岗位画像：四个岗位都加了交叉摸肩，仓储物流加了原地高抬腿；`coordination` 检测项可按岗位关闭或改为只记录。
- 改了 `motion` 阈值后，不用重新采集：`limbcheck motion 导出的报告.json` 重新分析（报告 JSON 里带了 `motion` 轨迹）。

## 3. 手部

手部完整性在第 1 步已完成（手指长度比 + 指尖轮廓复核 + 掌面覆盖率 + 掌心 / 手背两个视角都要拍到，见 [HANDS.md](HANDS.md)）。
本步骤把握拳 / 张开、拇指对捏的完成情况也计入肢体协调性。

## 4. 已知限制与后续优化

- 所有阈值都是建议初值，需要用真人样本校准，尤其是活动受限、动作不协调的阳性样本（目前只有合成序列和静态图验证）。
  校准方法：网页 demo 验证模式采集 → `limbcheck motion` 用不同阈值重跑 → 看误报 / 漏报。
- 单摄像头正面视角只能看到画面内的投影：前后方向的动作（如抬腿时大腿向前）通过投影长度变化估算，侧身会影响精度。
- 节律分析依赖帧率，低端手机掉帧（< 10 帧 / 秒）时间隔估计会变差；报告里记录了端侧帧率，可据此过滤。
- 协调性目前没有大模型一路；后续可以把关键帧拼图交给大模型做第二路判断，或采集数据训练专门的动作质量模型，输出同样的 findings 格式即可接入。
